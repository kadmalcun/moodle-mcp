# 利用者 PC での実機確認

Mac・Windows の実機と、ログイン後の取得は開発サーバーでは未確認。
提出の実行はこの確認の対象に含めない。利用者本人のアカウントで確認する。

## 手順

1. README の wheel または .mcpb の導入手順を実行する。Google Chrome または
   Microsoft Edge を使う場合は先にインストールする。
2. MCP でツール一覧を取得し、提出ツールがないことを確認する。
   `moodle_login` を呼び、専用のブラウザで学内ゲート・Google・Moodle にログインする。
   普段使いのブラウザにログイン済みでも、この専用プロファイルでは初回ログインが必要。
3. Moodle の画面になったら、その専用ブラウザのウィンドウをすべて閉じる。
   ツールが `logged_in: true` を返すことを確認する。
4. 締切・コース・お知らせ・活動を取得する。教材保存は新しい保存先を指定し、
   保存ファイルが読めること、同じ保存先への再保存は拒否されることを確認する。
5. クライアントを再起動して締切を取得し、ログインが保持されていることを確認する。
6. `moodle_login` で専用ブラウザを開き、手でログアウトして閉じる。
   ログイン要求が返ることを確認し、再度ログインして読み取りを試す。
7. 必要なら提出設定を有効にして MCP を再起動する。提出ツールが増えることを確認し、
   本人が選んだ課題・ローカルファイルで `confirm: false` の下見だけ行う。
   課題名、SHA-256、容量、同名ファイルの置換、制約・警告を確認する。
   `confirm: true` や CLI の `--confirm` は使わない。
8. 提出設定を無効にして再起動し、提出ツールが消えることを確認する。

CLI でも `login`・`deadlines`・`download` を試す。同一プロファイルを使う MCP は
先に止める。5分のアイドル後の再取得と、手動ブラウザを開いている間の読み取り拒否も確認する。

## 困ったとき

- Google 認証で拒否される: 通常プロセスで起動していることを確認し、Chrome または Edge を選択して再試行する。
- ブラウザが見つからない: `chrome` / `msedge` に指定したブラウザがインストール済みか確認する。
  Chromium を使う場合は README の `playwright install chromium` を実行する。
- 起動時にプロファイル使用中と出る: そのプロファイルを使う別の MCP / CLI / ログインウィンドウを閉じる。
- 画面なしエラー: サーバー・SSH セッションではなく、利用者 PC のデスクトップから実行する。
- uv ランタイム非対応: .mcpb の代わりに README の uvx による stdio 設定を使う。

問題報告には OS・CPU・アプリとブラウザの版、実行した操作、エラー文だけを記録する。
Cookie・専用プロファイル・パスワード・OAuth URL のクエリは共有しない。
